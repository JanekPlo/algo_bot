## Suggested next deliverable

**Decision D — risk-adjusted metrics module** (`algo_bot/metrics.py` + ADR-007).

Rationale:
- Metrics is a dependency for **E (risk module)** — max drawdown stop needs a max-DD calculation; risk module without metrics has to inline that logic or expose a half-baked interface.
- Metrics is a dependency for **F (walk-forward)** — every fold reports metrics; walk-forward without a metrics module would duplicate computation.
- Mathematically clean: pure functions over trade sequences / equity series. Easy to test without mocks (rule #3).
- Establishes conventions for the rest of Phase 1: annualization factor for crypto (24/7 trading, no calendar gaps), how to handle Calmar at zero DD, how to define profit factor when there are no losing trades, rolling vs static windows for Sharpe / Sortino.

Two alternatives are also defensible: tail of Decision C (write `log.md` deep reference + retrofit the five remaining files) is mechanical low-risk closure; cleanup of `executor.py` FIXME + `test_backtest.py` signature would give a clean test baseline before D/E/F land. Both are smaller in scope and lower in strategic ROI than D.

Janek picked **D**.
